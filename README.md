# Культяшка — планировщик перерождений

Приложение для составления планов в культяшке («Культивируй. Умри. Начни сначала»).
Посмертие выдаёт очки, магазин предлагает уроки, кости таланта, чистоту корней и накопители —
здесь всё это собирается в план, считается и выгружается в текстовом формате, принятом для планов.

* **Go + Jinja** (шаблоны — [gonja](https://github.com/NikolaLohinski/gonja), реализация Jinja2 для Go).
* **JS по минимуму и без общения с сервером**: конструктор целиком живёт в браузере
  (`static/engine.js` — расчёты, `static/builder.js` — интерфейс). На сервер уходит
  только явное «Сохранить». Боковая панель со сводкой, накопителями и секциями
  прокручивается сама, а не уезжает вниз вместе со страницей.
* Планы хранятся на сервере: один JSON-файл, который легко скопировать и посмотреть глазами.
* Регистрация: **ник + дискорд-хендл + пароль**. Дискорд не проверяется — по нему выдаётся
  доступ, если игрок забыл пароль (админка умеет сбросить пароль и показать временный).

## Что умеет

| Раздел | Что можно делать |
| --- | --- |
| Уроки | выбор, нумерация по порядку покупки, цена 5 × номер, проверка «можно взять как минимум n-ным уроком» (тег красный, пока условие нарушено, и зелёный, когда выполняется), фиксированные цены не занимают номер, перенос в «невыученные»; строки в конструкторе стоят в порядке покупки, поэтому сортировка двигает сами уроки, а не только номера |
| Обязательные позиции | «уже взято ею самой» и «обязательно по тексту»: такие позиции всегда в плане и не снимаются, а уже оплаченные занимают номер и списывают обычную цену («поцелуй Мелисандры» — первый урок, поэтому нумерация идёт со второго) |
| Условия каркаса | проверки вида «взять контроль пола ИЛИ фолиант после определения пола»: видны в боковой панели, невыполненные попадают в «Проверки» экспорта, а условия «на будущие жизни» выносятся отдельной памяткой |
| Награды за порядок | «последний бой» после «пинг систем»: потеря награды видна сразу и чинится одной кнопкой |
| Повторяемые покупки | «лестница в небо» дважды, «взять 1 фолиант» до трёх раз — у строки счётчик `×N` |
| Талант | шкалы: кость таланта (`dN` стоит N XP), число костей, плоский бонус |
| Чистота корней | максимум (+5% за 5 XP) и минимум с книжной скидкой — шаг `ceil(n / 2)`: 25 → 50 стоит 481 XP, как в планах игроков |
| Шансы | «один на миллиард» (200 XP) и «один на миллион у вас дома» (50 XP за процент) |
| Накопители | покупка за фиксированную цену и отдельная отметка «активирую»: заряд считается целыми единицами (0,8 — не заряд, 1 из 2 — уже заряд), прибавка за жизнь достанется в следующей жизни, а покупки («хардкор», «равновесие», «максимум зарядов», «скорость зарядки») учтены и в панели, и в выгрузке |
| Фолианты | «беру с собой» отмечается после урока метода и выкупа, сам выбор бесплатный: пока условий нет, галочка выключена и рядом написано, чего не хватает |
| Обновление каркаса | в панели «Каркас» видно, какой каркас лежит внутри плана, и есть кнопка «Обновить из готового»: покупки и отметки сохраняются, цены и условия становятся текущими, а если покупка из плана в новом каркасе больше не предлагается — о ней сообщают (каркас нельзя править молча) |
| Тренировки, телосложения, родословные, фолианты, заплатки | обычные покупки с фиксированной ценой; выкуп фолианта — отдельная покупка, трофейные методы бесплатны; выкуп без урока метода попадает в «Проверки» |
| Экспорт | текст плана с суммами и остатками по секциям, «Невыученные», «Не взято», итоговый остаток; копирование и скачивание `.txt` прямо из браузера |

Каркас под конкретное посмертие приложение **не разбирает само**: скелет магазина
(JSON) готовится вручную под эту смерть и загружается в план. После перерождения исчезают
только уроки: постоянная часть магазина — накопители, библиотека, шкалы, навыки — остаётся,
поэтому прошлые уроки («великий успех», «заряд великого успеха») в новый каркас не
переезжают, а права библиотеки и накопители в нём есть. Формат — в
[docs/karkas.md](docs/karkas.md), готовый пример — `internal/web/presets/08-zaskoruzlye-piramidy.json`
(жизнь 8, континент Заскорузлых пирамид: 1605,24148 XP, 50 позиций, уже купленный
первый урок и обязательный «пинг систем»). Цены этого каркаса сверены с планами
игроков, которые проверял ГМ: тест `TestPlansFromPlayers` повторяет каждый сданный
план покупка в покупку и сверяет остаток опыта.

## Локальный запуск

```bash
source scripts/goenv.sh          # кэши Go лежат внутри проекта (домашний каталог read-only)
go run .                         # http://127.0.0.1:8080
```

Настройки — переменными окружения:

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `KULTYASKA_ADDR` | `127.0.0.1:8080` | адрес прослушивания |
| `KULTYASKA_DB` | `data/kultyaska.db` | путь к JSON-базе |
| `KULTYASKA_ADMINS` | — | ники через запятую, которым сразу даются права админа |
| `KULTYASKA_SESSION_DAYS` | `30` | срок жизни сессии |
| `KULTYASKA_SECURE_COOKIES` | `0` | `1` — куки только по https (нужно за Cloudflare) |

Первый зарегистрированный пользователь становится администратором.

## Тесты

```bash
scripts/test.sh
```

Что проверяется:

* `go test ./...` — движок стоимости, экспорт (эталон в `internal/plan/testdata/export.golden`),
  веб-слой через `httptest` (регистрация, план из каркаса, сохранение, экспорт, админка, экранирование),
  а также `TestPlansFromPlayers` — 13 планов игроков на жизнь 8, сверенных покупка в покупку.
* `node tests/engine.test.js` — JS-движок конструктора сверяется с тем же эталоном, что и Go
  (кросс-проверка, чтобы предпросмотр в браузере и серверный экспорт не разъезжались).
* `node tests/builder.test.js` — интерфейс конструктора в jsdom: нумерация уроков, порядок строк,
  «невыученные», «не беру», шкалы, счётчик повторяемых покупок, доступность отметок накопителей
  и фолиантов (и зелёный тег «минимум n-ным», когда условие выполнено), поиск, сохранение,
  загрузка каркаса.

Эталон пересобирается командой `go test ./internal/plan -update`.

## Выкладка

```bash
./scripts/deploy.sh              # собрать и выложить
./scripts/smoke.sh https://…      # дымовая проверка по публичному адресу
```

Провайдеры в РФ нередко рубят 22-й порт, и тогда ssh падает с `Connection refused`,
хотя сервер жив: выкладку и `scripts/rssh` можно пустить через локальный прокси
(`scripts/ssh-relay.py` умеет HTTP CONNECT и SOCKS5):

```bash
KT_SSH_PROXY=socks5://127.0.0.1:10808 ./scripts/deploy.sh
KT_SSH_PROXY=http://127.0.0.1:10809 scripts/rssh 'sudo systemctl is-active kul-tyaska'
```

Скрипт собирает статический бинарник, кладёт его в `/opt/kul-tyaska/kultyaska`, ставит два
systemd-сервиса (`kul-tyaska.service` — приложение на `127.0.0.1:8080`, `kul-tyaska-tunnel.service` —
Cloudflare Tunnel с токеном из `.env`) и перезапускает их. База живёт в `/var/lib/kultyaska/kultyaska.json`.

Туннель запускается с `--url http://127.0.0.1:8080`: если в дашборде Cloudflare публичные хосты
не описаны, весь трафик туннеля уходит на приложение. Чтобы приложение открывалось по своему
домену, добавь публичный хост в дашборде (Networks → Tunnels → Public Hostname).

### Бесплатный постоянный адрес без дашборда

```bash
./scripts/setup-https.sh 162.254.85.195.nip.io
```

`nip.io` отдаёт доменное имя, указывающее на IP сервера, nginx проксирует его на приложение,
а Let's Encrypt выдаёт настоящий сертификат. Аккаунт Cloudflare для этого не нужен.
Адрес вида `https://<ip-сервера>.nip.io` работает сразу и не зависит от туннеля.

## Структура

```
main.go                     запуск и graceful shutdown
internal/plan/              модель плана, каркасы, движок стоимости, экспорт
internal/store/             JSON-хранилище: пользователи, сессии, планы
internal/auth/              пароли (PBKDF2-HMAC-SHA256, stdlib)
internal/web/               роуты, обработчики, шаблоны Jinja, статика, каркасы
internal/web/static/        app.css, engine.js (расчёты), builder.js (интерфейс)
deploy/                     systemd-юниты
scripts/                    goenv.sh, deploy.sh, smoke.sh, test.sh, rssh
tests/                      node-тесты JS-движка и конструктора
```
