# Каркас посмертия

Каркас — это скелет магазина под конкретную смерть. Его готовит Архивариус (или сам игрок)
в формате JSON, приложение ничего из текста посмертия не вытаскивает само. В конструкторе каркас
загружается кнопкой **«Каркас»**: можно вставить JSON, взять готовый из списка или скачать текущий.

## Как это выглядит

```json
{
  "name": "Жизнь 6 · континент Заскорузлых пирамид",
  "balance": 1605.24148,
  "earned": 1596.672,
  "subtotal": 672,
  "multipliers": ["Женский пол: ×1,5", "Тип смерти. Подвиг: ×2"],
  "notes": "пара строк контекста, попадут в план",
  "shop": [ … ],
  "ladders": [ … ],
  "accumulators": [ … ],
  "folios": [ … ]
}
```

| Поле | Обязательное | Смысл |
| --- | --- | --- |
| `name` | нет | название посмертия (показывается в списке каркасов и в шапке) |
| `balance` | да | сколько XP доступно к трате |
| `earned` / `subtotal` | нет | итог посмертия и подытог — для справки в шапке |
| `multipliers` | нет | множительные параметры (просто список строк) |
| `shop` | да, минимум одна позиция | всё, что можно купить |
| `ladders` | нет | шкалы; если не указать — возьмутся базовые из книги |
| `accumulators` | нет | накопители с зарядами |
| `folios` | нет | фолианты библиотеки |

## Позиция магазина (`shop[]`)

```json
{
  "key": "lesson:bud_silnee",
  "kind": "lesson",
  "section": "lessons",
  "title": "будь сильнее",
  "min_lesson": 1,
  "cost": 0,
  "fixed": false,
  "desc": "Максимальная чистота корней +5%, талант до 1d2.",
  "tags": ["one_chance"]
}
```

| Поле | Смысл |
| --- | --- |
| `key` | стабильный ключ (латиницей). Если не указать — сгенерируется из `title` |
| `kind` | `lesson` — урок (цена зависит от номера), `item` — обычная покупка, `patch` — заплатка, `folio` — фолиант, `accumulator` — накопитель, `revenge` — месть |
| `section` | `lessons`, `patches`, `talent`, `roots`, `chances`, `accumulators`, `physique`, `bloodline`, `trainings`, `folio`, `other` |
| `title` | краткое название — именно оно попадает в план |
| `cost` | цена для фиксированных покупок; у растущих уроков не используется |
| `fixed` | `true` — цена фиксированная: урок не занимает номер и не поднимает цену следующих |
| `min_lesson` | «можно взять как минимум n-ным уроком» |
| `desc` | полный текст из посмертия (в конструкторе прячется под «описание») |
| `tags` | `one_chance` (только один раз в жизни), `trophy` (трофей), `osvoeno` (освоено), `defer_slot` (+1 слот невыученных), `fixed_price` |
| `requires` / `excludes` | ключи уроков, без которых нельзя / с которыми несовместимо |
| `no_defer` | «на этот урок нельзя применить невыученные уроки» |
| `locked` | план **обязан** содержать позицию: её взяла сама Ли Лун или она не станет рассматривать план без неё. В конструкторе кнопки «беру / невыученный / не беру» заблокированы |
| `lock_note` | причина блокировки — показывается в интерфейсе и в предупреждениях |
| `already_paid` | позиция уже оплачена в тексте. Урок занимает свой номер, но опыт за него не списывается; в плане печатается с пометкой «уже куплено». Автоматически делает позицию `locked` |

## Позиции, которые Ли Лун уже взяла

В конце посмертия бывают системные приписки: «Ли Лун уже купила первый урок»,
«не станет рассматривать планы, в которых не будет урока …». Их надо переносить
в каркас, иначе план начнёт противоречить тексту:

```json
{
  "key": "lesson:poceluy_melisandry",
  "kind": "lesson",
  "section": "lessons",
  "title": "поцелуй Мелисандры",
  "locked": true,
  "already_paid": true,
  "lock_note": "первый урок: Ли Лун уже купила его сама, поэтому нумерация идёт со второго"
}
```

Такой урок встаёт первым (уже оплаченные позиции всегда впереди, в порядке магазина),
следующий урок получает номер 2 и стоит 10 XP — как в тексте.

## Условия каркаса (`requirements[]`)

Проверки, которым обязан удовлетворять план, — например, «взять контроль пола
**или** фолиант после определения пола»:

```json
"requirements": [
  {
    "kind": "any_of",
    "keys": ["item:vybor_pola", "folio:vzyat_posle_pola"],
    "message": "чтобы снова встретить Джона Сноу, нужно «контроль пола» или «взять фолиант после определения пола»"
  }
]
```

`kind` — `any_of` (достаточно одной позиции) или `all_of` (нужны все). В конструкторе
условия видны в боковой панели с галочкой или крестиком, а невыполненные попадают
в «Проверки» экспорта. Ключи, которых нет в `shop`, при загрузке отбрасываются.

## Шкала (`ladders[]`)

```json
{
  "key": "talent.die",
  "section": "talent",
  "title": "кость таланта",
  "unit": "d",
  "from": 1, "to": 25, "step": 1, "value": 1,
  "cost": { "type": "to_value", "rate": 1 },
  "note": "кость dN стоит N XP"
}
```

`unit: "d"` печатает значение как `d9`, `%` — как процент.

Виды цены (`cost`):

| `type` | Цена шага на уровень `n` |
| --- | --- |
| `to_value` | `n × rate` |
| `linear` | `rate` за каждый шаг |
| `per_level` | `n × per_level` |
| `table` | `table[n]` (например `[0, 1, 10, 200]`) |

Дополнительно `"ceil": true` округляет цену шага вверх (так работает скидка «цена корней уменьшена вдвое»).

## Накопители и фолианты

```json
"accumulators": [
  { "name": "горожане", "charges": 0.8, "max": 1, "rate": 20, "note": "рождение горожанином" }
],
"folios": [
  { "name": "метод Непроглядного Тумана", "take": false, "cost": "50 XP" }
]
```

`charges`/`max` — заряды и максимум, `rate` — сколько процентов заряда добавляет прожитая жизнь,
`take` — берём ли фолиант с собой в следующую жизнь.

## Как готовится каркас

1. Берём текст посмертия: баланс (`Баланс: … XP`), магазин, уроки и их ограничения.
2. Уроки переносим в `shop` с `kind: "lesson"`; фиксированные цены («0 XP», «трофей», «не идёт
   в счётчик») отмечаем `fixed: true`; приписки «можно взять как минимум n-ным уроком» — в `min_lesson`.
3. Тарифы шкал (талант, корни, шансы) — в `ladders`; всё остальное (тренировки, заплатки,
   телосложения, родословные, фолианты) — обычными позициями `shop`.
4. Накопители — в `accumulators`, библиотека — в `folios`.
5. Готовый каркас кладём в `internal/web/presets/*.json`, и он появляется в списке готовых
   (кнопка «Создать план» на странице планов), либо просто вставляем JSON в конструкторе.
