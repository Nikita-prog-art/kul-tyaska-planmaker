# Каркас посмертия

Каркас — это скелет магазина под конкретную смерть. Его готовит Архивариус (или сам игрок)
в формате JSON, приложение ничего из текста посмертия не вытаскивает само. В конструкторе каркас
загружается кнопкой **«Каркас»**: можно вставить JSON, взять готовый из списка или скачать текущий.

## Как это выглядит

```json
{
  "name": "Жизнь 6 · континент Заскорузлых пирамид",
  "balance": 1605.24148,
  "earned": 1596.672,
  "subtotal": 672,
  "deferred_slots": 2,
  "multipliers": ["Женский пол: ×1,5", "Тип смерти. Подвиг: ×2"],
  "notes": "пара строк контекста, попадут в план",
  "shop": [ … ],
  "ladders": [ … ],
  "accumulators": [ … ],
  "folios": [ … ]
}
```

| Поле | Обязательное | Смысл |
| --- | --- | --- |
| `name` | нет | название посмертия (показывается в списке каркасов и в шапке) |
| `balance` | да | сколько XP доступно к трате |
| `earned` / `subtotal` | нет | итог посмертия и подытог — для справки в шапке |
| `multipliers` | нет | множительные параметры (просто список строк) |
| `shop` | да, минимум одна позиция | всё, что можно купить |
| `ladders` | нет | шкалы; если не указать — возьмутся базовые из книги |
| `accumulators` | нет | накопители с зарядами |
| `folios` | нет | фолианты библиотеки |
| `deferred_slots` | нет | сколько слотов «невыученных уроков» уже открыто к этой смерти (по умолчанию 1). Второй слот даёт урок «невыученные уроки всё ещё не выучены», выученный в прошлой жизни, — поэтому в каркасе это просто число; взятый сейчас урок с тегом `defer_slot` добавляет ещё один |

## Позиция магазина (`shop[]`)

```json
{
  "key": "lesson:bud_silnee",
  "kind": "lesson",
  "section": "lessons",
  "title": "будь сильнее",
  "min_lesson": 1,
  "cost": 0,
  "fixed": false,
  "desc": "Максимальная чистота корней +5%, талант до 1d2.",
  "tags": ["one_chance"]
}
```

| Поле | Смысл |
| --- | --- |
| `key` | стабильный ключ (латиницей). Если не указать — сгенерируется из `title` |
| `kind` | `lesson` — урок (цена зависит от номера), `item` — обычная покупка, `patch` — заплатка, `folio` — фолиант, `accumulator` — накопитель, `revenge` — месть |
| `section` | `lessons`, `patches`, `talent`, `roots`, `chances`, `accumulators`, `physique`, `bloodline`, `trainings`, `folio`, `other`. Урок (`kind: "lesson"`) попадает в «Уроки», что бы тут ни стояло: урок на телосложение или родословную — такой же урок с номером и ценой |
| `title` | краткое название — именно оно видно в конструкторе |
| `short` | ещё короче, только для выгрузки: «поцелуй Мелисандры» → «Мелисандра», «водное телосложение (обычное)» → «водное тело». Если не задано, берётся из встроенной карты по `key`, а без ключа печатается `title` |
| `cost` | цена для фиксированных покупок; у растущих уроков не используется |
| `fixed` | `true` — цена фиксированная: урок не занимает номер, не поднимает цену следующих и в плане идёт отдельным разделом «Уроки с фиксированной ценой» |
| `min_lesson` | «можно взять как минимум n-ным уроком» |
| `desc` | полный текст из посмертия (в конструкторе прячется под «описание») |
| `tags` | `one_chance` (только один раз в жизни), `trophy` (трофей), `osvoeno` (освоено), `defer_slot` (+1 слот невыученных), `fixed_price` |
| `requires` / `excludes` | ключи покупок, без которых позиция не имеет смысла / с которыми несовместима. Взятая позиция с невыполненным `requires` попадает в «Проверки»: «выкупить метод Тумана» взят без «метод Непроглядного Тумана» |
| `no_defer` | «на этот урок нельзя применить невыученные уроки» |
| `repeat` | сколько раз позицию можно взять в одном плане (`2` — «лестница в небо», `3` — «взять 1 фолиант»). В конструкторе у такой строки есть кнопки «−/+» и счётчик `×N`, в план она уезжает строкой `название ×2` |
| `locked` | план **обязан** содержать позицию: её взяла сама Ли Лун или она не станет рассматривать план без неё. В конструкторе кнопки «беру / невыученный / не беру» заблокированы |
| `lock_note` | причина блокировки — показывается в интерфейсе и в предупреждениях |
| `already_paid` | позиция уже взята ею самой до плана. В плане печатается с пометкой «уже куплено», опыт за неё списывается как обычно, а урок занимает свой номер — нумерация продолжается со следующего. Автоматически делает позицию `locked` |

## Позиции, которые Ли Лун уже взяла

В конце посмертия бывают системные приписки: «Ли Лун уже купила первый урок»,
«не станет рассматривать планы, в которых не будет урока …». Их надо переносить
в каркас, иначе план начнёт противоречить тексту:

```json
{
  "key": "lesson:poceluy_melisandry",
  "kind": "lesson",
  "section": "lessons",
  "title": "поцелуй Мелисандры",
  "locked": true,
  "already_paid": true,
  "lock_note": "первый урок: Ли Лун уже купила его сама, поэтому нумерация идёт со второго"
}
```

Такой урок встаёт первым (уже взятые позиции всегда впереди, в порядке магазина),
следующий урок получает номер 2 и стоит 10 XP — как в тексте. Опыт за первый урок
план считает потраченным наравне с остальными: 5 XP уходят из остатка.

`already_paid` работает и для не-уроков — заплаток, фолиантов, покупок:

```json
{
  "key": "patch:otkluchenie_trenirovok",
  "kind": "patch",
  "section": "patches",
  "title": "отключение тренировок",
  "cost": 0,
  "locked": true,
  "already_paid": true,
  "lock_note": "Ли Лун уже взяла эту заплатку сама"
}
```

В плане она печатается как `Заплатки: без тренировок: 0 (уже куплено)` и снять её нельзя.

## Условия каркаса (`requirements[]`)

Проверки, которым обязан удовлетворять план, — например, «взять контроль пола
**или** фолиант после определения пола»:

```json
"requirements": [
  {
    "kind": "any_of",
    "keys": ["item:vybor_pola", "folio:vzyat_posle_pola"],
    "message": "чтобы снова встретить Джона Сноу, нужно «контроль пола» или «взять фолиант после определения пола»"
  }
]
```

`kind` — `any_of` (достаточно одной позиции) или `all_of` (нужны все). В конструкторе
условия видны в боковой панели с галочкой или крестиком, а невыполненные попадают
в «Проверки» экспорта. Ключи, которых нет в `shop`, при загрузке отбрасываются.

Если условие касается не этого плана, а будущих жизней (например, Джона Сноу можно
переродить только через жизнь), ставьте `"soft": true`. Тогда оно не считается
проверкой: в «Проверки» не попадает, красным не пугает и остаётся памяткой
в боковой панели конструктора — в текст плана такие условия не идут, там только покупки.

## Награда за порядок (`reward_after`)

Если позиция даёт что-то только при определённом месте в плане — как «последний бой»,
который даёт квестовую награду, если взят после «пинг систем»:

```json
{
  "key": "lesson:posledniy_boy",
  "kind": "lesson",
  "section": "lessons",
  "title": "последний бой",
  "reward_after": {
    "key": "lesson:ping_sistem",
    "title": "квестовая награда",
    "note": "итоговый бонус вырос до +4% к атаке и +4% к защите",
    "lose": "без неё бонус остаётся +2% к атаке и +2% к защите"
  }
}
```

В конструкторе у такой позиции появляется пометка «после «пинг систем»» и подсказка,
которая переключается на «награда получена» или «взято раньше — не достанется»
(с кнопкой «поставить после …»). Порядок проверяется по очереди покупок: если позиция
стоит раньше опорной, в «Проверки» уходит предупреждение, а награда в план не попадает.
Кнопка «Разложить уроки по требованиям» уважает награды — она не поставит «последний
бой» перед «пинг систем». Автоматически конструктор порядок больше не меняет:
как расставил, так и сохранится.

Раскладываются только нумеруемые уроки: «уже взято», уроки с фиксированной ценой
(«фиксированная цена», «трофей», «освоено») и отложенные невыученные остаются на
своих местах — иначе они сбили бы нумерацию. Самый нетребовательный урок встаёт
первым, самый требовательный («минимум 10-м») — последним: это единственная
раскладка, при которой требования выполняются, если их вообще можно выполнить.
Если нарушений нет, кнопка ничего не двигает и честно пишет «менять нечего».

## Порядок строк в конструкторе

Секция «Уроки» рисуется **в порядке покупки**, а не в порядке магазина: сверху стоит
урок, который берут первым, и номера идут сверху вниз. Поэтому кнопки «↑/↓» и
«Разложить уроки по требованиям» двигают сами строки, а не только числа в бейджах.
Дальше идут отложенные (невыученные) уроки, а за ними — всё, что ещё не решено.

## Шкала (`ladders[]`)

```json
{
  "key": "talent.die",
  "section": "talent",
  "title": "кость таланта",
  "unit": "d",
  "from": 22, "to": 25, "step": 1, "value": 22,
  "cost": { "type": "to_value", "rate": 1 },
  "note": "кость уже d22; ступень стоит свой номер: d23 — 23 XP"
}
```

**`from` — это то, что у Ли Лун уже есть** (её постоянные улучшения из прошлых жизней).
Опыт считается только за прирост `from → value`, поэтому в каркасе обязательно
указывайте, что уже куплено: если поставить `from: 1`, план начнёт списывать опыт
за все ступени с самого начала. В конструкторе поле «уже есть» рядом со шкалой
редактируемое — если состояние в каркасе разошлось с игрой, это можно поправить на месте.

`unit: "d"` печатает значение как `d9`, `%` — как процент. Необязательное
`short` — название для выгрузки: «максимальная чистота корней» → «корни макс».

Виды цены (`cost`):

| `type` | Цена шага на уровень `n` |
| --- | --- |
| `to_value` | `n × rate` |
| `linear` | `rate` за каждый шаг |
| `per_level` | `n × per_level` |
| `table` | `table[n]` (например `[0, 1, 10, 200]`) |

Дополнительно `"ceil": true` округляет цену шага вверх (так работает скидка «цена корней уменьшена вдвое»).
Так, в жизни 8 минимальная чистота корней стоит `ceil(n / 2)` и задаётся как
`{ "type": "to_value", "rate": 0.5, "ceil": true }`: 25 → 50 стоит 481 XP, 25 → 43 — 315 XP,
25 → 70 — 1091 XP — ровно те числа, что стоят в планах игроков.

`hidden: true` убирает шкалу из конструктора: так помечены ступени, которые Ли Лун
уже купила в прошлых жизнях (`chance.million`) — в этой жизни их не предлагают.

## Накопители и фолианты

```json
"accumulators": [
  { "name": "горожане", "short": "горожане", "charges": 0.8, "max": 1, "rate": 20,
    "note": "0,8 заряда из 1: целого заряда нет, +20% за жизнь придёт в следующей жизни" },
  { "name": "хардкор", "charges": 0, "max": 1, "rate": 0, "requires": ["item:hardkor"] }
],
"folios": [
  { "name": "метод Непроглядного Тумана", "take": false, "cost": "50 XP",
    "requires": ["lesson:metod_neproglyadnogo_tumana", "folio:vykupit_tuman"] }
]
```

`charges`/`max` — сколько зарядов накоплено на момент перерождения и сколько их всего,
`rate` — сколько процентов заряда добавляет прожитая жизнь, `take` — берём ли фолиант
с собой в следующую жизнь. Про заряды в тексте ничего нет («хардкор», «равновесие зла
и добра») — оставьте нули и укажите `requires`: покупка сама зарядит накопитель
(см. `effects`), а в панели он до покупки будет выключен.

Заряд считается **целыми единицами**: 0,8 — ещё не заряд, а 1 из 2 — уже заряд,
и его можно тратить. Прибавка `rate` начисляется за прожитую жизнь, то есть в состояние
перерождения она не входит — «горожане» с 0,8 заряда в это перерождение не тратятся.

`requires` — то же, что у позиции магазина: список ключей, которые надо взять раньше. Битые
ссылки (ключей нет в `shop`) каркас выбрасывает при разборе, иначе накопитель или фолиант
остались бы недоступными навсегда.

Покупки меняют накопитель через `effects` у позиции магазина:

```json
{ "key": "item:hardkor", "title": "накопитель «хардкор»", "cost": 20,
  "effects": [{ "accumulator": "acc:hardkor", "charges": 1 }] },
{ "key": "lesson:maksimum_zaradov_gorozhan", "title": "максимум зарядов накопителя «горожане»",
  "effects": [{ "accumulator": "acc:gorozhane", "max": 1 }] },
{ "key": "lesson:skorost_zaradki_gorozhan", "title": "увеличение скорости зарядки накопителя «горожане»",
  "effects": [{ "accumulator": "acc:gorozhane", "rate": 25 }] }
```

* `charges` — прибавить заряды сразу (без него «хардкор» и «равновесие» так и останутся пустыми);
* `max` — поднять максимум зарядов;
* `rate` — задать новую скорость зарядки в процентах за жизнь (не прибавляется, а заменяет).

Эффекты видны и в панели, и в выгрузке: накопитель печатается с состоянием на момент
перерождения, например `хардкор (1/1)` или `горожане (0,8/2, +25% за жизнь)`. Эффекты с чужим
ключом накопителя каркас выбрасывает при разборе.

В конструкторе это отдельная панель **«Накопители и фолианты»**: галочками отмечается, что
активируем и какие фолианты берём. В плане рядом с покупками появляются строки
«Активация накопителей: хардкор (1/1)» и «Беру с собой: Туман» — только про то, что берём.
Название для выгрузки можно задать полем `short` у накопителя и у фолианта.

Отметка ставится только тогда, когда план её заслужил:

* **накопитель** — если у него есть хотя бы один целый заряд (с учётом `effects`), а при
  `requires` — ещё и нужная покупка. Незаряженный и некупленный отметить нельзя, рядом
  написано, чего не хватает;
* **фолиант** — если взят урок метода и оплачен выкуп (оба ключа в `requires`). Сам выбор
  фолианта бесплатный: он ничего не стоит сверх этих покупок. Пока условия нет, галочка
  выключена, а сохранённый план не может содержать такую отметку — `Normalize` её снимает.

Если снять покупку, отметка в конструкторе гаснет сама: незачем платить за фолиант, который
никуда не уедет.

## Методы, трофеи и библиотека

Разделять «выучить метод» и «выкупить фолиант» — две разные покупки, и в планах они
стоят в разных секциях:

* урок метода — обычный урок (`kind: "lesson"`, без `fixed`): занимает номер и стоит как
  все уроки. В плане он печатается в «Уроки» коротко (например, «13. Туман: 25»);
* трофейный метод — урок с `fixed: true` и `cost: 0`, он бесплатен, номер не занимает и печатается
  в разделе «Уроки с фиксированной ценой»;
* выкуп фолианта — обычная позиция в разделе `folio` с фиксированной ценой
  («выкуп Тумана: 50»). Выкуп и урок друг друга не заменяют:
  у выкупа в `requires` стоит ключ урока метода, иначе взятый выкуп попадёт в «Проверки».

Так же разделяются права и покупки библиотеки: «взять 1 фолиант» платит за право, а какие
именно фолианты уезжают с собой — отмечается в панели фолиантов (и ничего не стоит).

## Выгрузка

Текст плана — это список строк, по одной на раздел:

```
Уроки: 1. Мелисандра: 5 (уже куплено), 2. ученье: 10, 3. алхимик: 15
  Сумма: 30, ост. 1575
```

* позиции внутри раздела перечисляются через запятую в одну строку, суммы и остаток —
  отдельной строкой с отступом;
* названия короткие (`short`), чтобы строка влезала в сообщение: «Мелисандра», «водное тело»;
* награда за порядок печатается пометкой «(с бонусом)», а не полным описанием: бонус один раз
  описан в каркасе, в плане он только занимал бы строку;
* «На будущие жизни» и заметки каркаса в план не попадают: план — это покупки, памятка
  живёт в конструкторе;
* переносов внутри строк в самом тексте нет: их делает показ — страница экспорта
  переносит по ширине окна, чат тоже, — а при копировании каждый раздел остаётся одной строкой.

## Как готовится каркас

1. Берём текст посмертия: баланс (`Баланс: … XP`), магазин, уроки и их ограничения.
2. После перерождения исчезают **только уроки**. Если «великий успех» или «максимум зарядов»
   предлагались в прошлый раз, а в этом списке их нет — в `shop` их быть не должно. А постоянная
   часть магазина (накопители, шкалы, навыки, права библиотеки вроде «взять 1 фолиант»)
   остаётся и в каркас попадает, даже если в этом посмертии её просто не перепечатали.
   Опции библиотеки не схлопывать: «взять 1 фолиант» (5 XP) и «взять 1 фолиант, получив доступ
   на стадии Накопления Ци» (10 XP) — две разные покупки.
3. Уроки переносим в `shop` с `kind: "lesson"`; фиксированные цены («0 XP», «трофей», «не идёт
   в счётчик») отмечаем `fixed: true`; приписки «можно взять как минимум n-ным уроком» — в `min_lesson`.
4. Тарифы шкал (талант, корни, шансы) — в `ladders`; всё остальное (тренировки, заплатки,
   телосложения, родословные, фолианты) — обычными позициями `shop`.
5. Накопители — в `accumulators`, библиотека — в `folios`.
6. Готовый каркас кладём в `internal/web/presets/*.json`, и он появляется в списке готовых
   (кнопка «Создать план» на странице планов), либо просто вставляем JSON в конструкторе.
7. Сверяем цены с планами игроков: тест `TestPlansFromPlayers` в `internal/plan/plan_test.go`
   повторяет сданные планы покупка в покупку и сверяет остаток XP. Если он падает —
   расходится каркас, а не план.
8. Поправки в каркасе доходят до уже созданных планов только через «Каркас» → «Обновить
   из готового»: в самом плане лежит своя копия магазина.
